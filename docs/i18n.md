# Languages — read before adding or changing any text a person reads

One install speaks one language. `CRM_LOCALE` chooses it: `en` (the default) or
`pt-BR`. There is no per-user locale and no locale in the URL, for the same reason
there are no organizations — a value that is always the same is configuration,
not a row.

## Where the words live

`packages/i18n/messages/<locale>/<namespace>.json`. English is the source: its
shape is the `Messages` type, so a key that is missing in English is a type error
at the call site. `packages/i18n/test/parity.spec.ts` fails when another locale is
missing a key, has one English lacks, or interpolates different arguments.

| Namespace | Covers |
| --- | --- |
| `ui` | `packages/ui` components |
| `shell` | App chrome: header, icon rail, page shell, mobile nav, layout, enrichment queue |
| `auth` | `app/(landing)` sign-in, onboarding, grant-access; `components/auth-shell.tsx` |
| `dashboard` | The overview page: summary, sales dashboard, greeting, charts |
| `lists` | Companies, contacts and deals pages; `detail-sheet.tsx` |
| `dataTable` | `components/data-table` |
| `records` | `components/crm`: record sheets, timeline, agent conversations, website activity |
| `agentBuilder` | `components/agent-builder`, `app/(app)/[slug]/(agent-builder)`, `components/slack`, `agent-clarification-composer.tsx` |
| `settings` | `app/(app)/[slug]/settings` |
| `api` | Messages the API sends that the app shows: errors, toasts |

The landing page (`components/landing`, `app/(landing)/page.tsx`) is not
translated. It markets this product and is off unless `IS_MARKETING="true"`.

## How to use them

- **Client component**: `const t = useTranslations("records");` then
  `t("sheet.title")`.
- **Server component**: `const t = await getTranslations("records");`.
- **Outside React** (a `lib` helper that returns a label, the API, route
  handlers): `import { translator } from "@crm/i18n/translator"`, then
  `const t = translator("records");` inside the function, not at module scope.
  It works in the browser too. A shared `lib` helper keeps its signature and
  translates inside, so its callers do not change.
- **Plurals and counts use ICU**, never string concatenation:
  `"contactCount": "{count, plural, one {# contact} other {# contacts}}"`.
  `formatCount` from `@crm/ui/lib/format` is English-only; replace it at the call
  site with a message.
- **Rich text** uses `t.rich("key", { link: (chunks) => <a>{chunks}</a> })`, not
  a sentence split across three keys. Word order differs between languages.
- **Dates, numbers and money** go through `@crm/ui/lib/format` or
  `components/local-date-time.tsx`, which read the locale. Never write
  `"en-US"` or `undefined` as a locale.

## Keys

- camelCase, nested by screen then element: `dealSheet.fields.amount`.
- A key names what the text is for, not what it says: `emptyState.title`, not
  `noDealsYet`.
- One namespace per area, owned by that area. Do not reach into another area's
  namespace; duplicate a word instead. Two screens that say "Save" today may not
  tomorrow.

## What is not translated

- Data: a company's name, a stage a rep created, a custom field's label. Those are
  rows, and the rep chose the words.
- Enum *values* sent to the API. Translate the label shown for them.
- Log lines, telemetry, and errors a person never sees.
- Brand and product names: Google, Gmail, Slack, LinkedIn, Context, HubSpot.

## pt-BR style

Write for a Brazilian sales rep. Short, direct, informal "você". Correct accents.
No em dash (—) as punctuation; the parity test checks. A lone `—` for an empty
value is fine. Straight quotes.

## The agent

The research agent writes in the configured language: briefs, facts it records as
prose, the reason for a recheck, answers on the Agent tab. The rule is appended to
its instructions from `CRM_LOCALE`. Evidence it quotes (an email, a signature
block) stays in the language it was written in.

## Changing the language

Set `CRM_LOCALE` (and `CRM_TIME_ZONE`) on the app, the API and the agent, then
redeploy all three. The app reads the value at build time.
